# A+ 和风留白：聊天收放与角色主题色

用户已选择 A 的简洁布局。本目录保留 2026-09-06 的独立原型，不连接生产数据；2026-09-07 起正式客户端接入记录见 [阶段 0–2](../../a-plus-client.md)，前两轮设计稿继续保留。

## 设计选择

- 五个文字入口不变：陪伴、工作台、能力、角色、设置。移除品牌、卡片和工具的装饰图标。
- 右侧聊天可收起；客户端让出宽度给房间，壁纸构图采用浮动聊天，不改变场景宽度。关闭聊天后保留明确的文字恢复入口。
- 中性暖白界面与自然色房间，默认樱粉强调色；提供草绿、樱粉、青蓝、莓红四种色板。不修改模型材质、不读取角色卡或个人数据。
- 同一个 WebGL 视口与聊天 DOM 在布局切换中保留，草稿不清空，主题色变化不重新加载角色。能力等页面隐藏房间，停止绘制；场景采用按需绘制，无自主动作。
- 能力分类保持感知与交互、效率工具、生活与陪伴。初始语音、屏幕、OCR、截屏翻译均未配置/未启用；音乐待办不默认添加。模块可排序/移除，纯加号打开模块库，不触发授权或设备采集。
- 桌宠仅场景、角色、短气泡、输入；悬停或聚焦展示文字控制，可切透明背景。实际窗口拖动/隐藏仍由未来原生客户端完成。

## 复用与预览

依赖当前仓库 `frontend/node_modules` 中的 Three.js、three-vrm、Playwright，以及仓库示例 VRM；不下载新依赖、不接外网。服务仅监听 loopback，仅支持 GET/HEAD，白名单引用已有房间、能力元数据和示例模型，不暴露运行数据。

```powershell
& D:\Tools\nodejs\node.exe docs/ui/concepts/a-plus-v1/serve.mjs 8878
& D:\Tools\nodejs\node.exe docs/ui/concepts/a-plus-v1/capture.mjs
```

默认预览为 `http://127.0.0.1:8878/`，占用时自动改用空闲端口并输出地址。

- `/?theme=sage`：原 A 的草绿；`theme=sakura|blue|berry`：主题变体。
- `/?chat=closed`：客户端收起聊天。
- `/?mode=wallpaper&chat=closed`：壁纸构图；`chat=open`：壁纸聊天展开。
- `/?mode=pet`：配合 480×420 视口查看；`&transparent=1`：透明背景。
- `/?page=capabilities`：能力页。
- `/board.html`、`/board.html?themes=1`：布局与主题色对照。
- Esc 返回客户端；模块库中 Esc 只关闭模块库。页面不拦截系统快捷键。

## 原生壁纸边界

这里的“壁纸预览”只是隐藏导航后的网页构图，不调用浏览器全屏，也没有 Windows 桌面层、窗口置底、鼠标穿透、托盘、后台守护或登录自启。默认场景静态，不代表角色自主生活。

真实实现需要单独的 Tauri/Windows 桌面承载适配器，优先复用主会话和互斥视口，不能只把普通全屏窗口设为最底就宣称桌面壁纸可用。后续需验证桌面图标与任务栏关系、Explorer 重启恢复、多屏/DPI、Win+D、锁屏/遮挡暂停、退出恢复、输入聚焦，以及始终可用的返回客户端入口；不静默启用输入穿透或系统权限。

布局 A 不必绑定低饱和角色：色板由用户选择，将来可以读角色包的显式主题配置。增强二次元感更依赖角色表情、镜头和房间资源，不能只靠整屏高饱和粉色；更换角色后应重新验证对比度与面部构图。
