## 查看设计

从仓库根运行：

```powershell
node docs/ui/concepts/warm-home-v1/serve.mjs
```

默认使用 `http://127.0.0.1:8876`；端口占用时自动选择空闲端口并打印实际地址。
依赖仓库已有的 `frontend/node_modules`，不需要启动 Python Core 或 Tauri。
服务只读映射当前设计目录、必要 Three.js 依赖和指定示例 VRM，不暴露运行数据目录。

- `index.html`：设计预览，顶栏切换午后/夜晚/工作和客户端/桌宠。
- `board.html?theme=afternoon`、`evening`、`work`：三张配对设计板。
- `?theme=work&library=1`：模块库展开状态。
- `?view=pet&theme=afternoon`：480×420 桌宠构图；悬停或键盘聚焦显示控制。
- `?raw=1`：隐藏评审工具栏，以浏览器视口作为客户端或桌宠大小，用于截图。

## 设计与评审边界

午后以暖白、鼠尾草绿和樱粉表达日常陪伴；夜晚沿用同一套组件，调整房间照明和界面明度；
工作台采用功能与场景分区，任务/笔记/模型策略以同尺寸模块显示，末尾虚线块中央只有加号。
房间和角色占据实际场景区域，不把角色关进装饰性预览卡片。

客户端与桌宠在预览中互相切换，当前草稿和模块排序只保存在同页内存。每次只有一个 3D
视口；同场景的界面重绘保留画布，隐藏时不持续渲染。刷新恢复设计示例。原生双窗口状态
同步、拖动、置顶、关闭语义和持久化均需选稿后单独实现，浏览器交互不是原生验收。

模块库可添加、移除、排序，重复添加被阻止。添加卡片不启用功能，也不授予权限；未配置和
未授权状态明确保留。移除只改变页面布局，不删除数据或修改全局能力。发送按钮不可用，
不会真的发送或伪造新的助手回复。角色与设置只展示入口和状态草案，详细配置交互不在本轮。

桌宠默认场景、角色、短回复和输入框；可收起输入、隐藏预览或关闭场景背景。透明背景是
表现选项，不是第三种模式。场景为固定静态姿态，不包含行走、日程、生活状态机或主动发言。
“休息/工作”等字样和时钟均为构图示例，非已实现的模拟结果。

## 渲染问题复用

- VRM 静态首帧：模型缩放和定位后，若只更新骨骼、不更新 VRM，可能出现衣物拉长或材质黑块。
  本稿在姿态完成后执行 `springBoneManager.reset()`、`vrm.update(0)`、`updateMatrixWorld(true)`；
  三种构图重导出已确认恢复。单纯调整灯光不能修复这种首帧同步问题。
- 夜间变量：仅覆盖 `--ink` 不会改变已继承的根文字颜色，外壳需要 `color:var(--ink)`；
  输入 placeholder 也应明确引用主题色，不能依赖浏览器默认值。
- 透明 PNG：只清除 WebGL 背景不够，raw 桌宠的 html/body/外壳均需透明；截图断言检查实际 alpha。
- 窄屏工作台：场景排在屏外时按需渲染会等到进入视口；明确场景 `order:-1`，避免切回后等不到首帧。
