## 三、H01–H06：高难实现包

### H01：Harness 中立契约与可信授权

**对应：R02、R11、R13。依赖：H00。**

#### A. 可替换架构

固定依赖方向：

```text
产品界面与宿主装配
        ↓
独立增强核心
        ↓
版本化窄接口
        ↓
DSH / 其他Harness / API适配器
```

复用现有 `AgentRuntime`、注册表、开发执行接口，不建立大型 `HostContext`。

本轮稳定以下对象：

| 对象 | 关键内容 |
|---|---|
| `RuntimeBinding` | Harness、稳定实例、发行组合、适配版本、执行模式 |
| `ExternalSessionRef` | Harness、实例、原始会话与回合引用 |
| `CapabilityEvidence` | 能力、支持状态、限制、实际验证来源 |
| `ModelInvocation` | 工作版本、操作 ID、用途、候选、结构化输入和限制 |
| `InvocationReceipt` | 发送事实、结果引用、usage、价格和资源回执 |
| `RecoveryAssessment` | 可确认事实、未决操作、安全接续条件 |
| `MergePreview` | 文件清单、前后摘要、验证引用、请求版本 |

具体 Harness 原始对象只留在适配器内部。需要保留的诊断数据与产品契约隔离。

稳定实例与启动实例分别记录：同一 profile 重启可延续来源身份，但旧进程令牌失效。

#### B. 可信确认

当前 Host/Origin 检查不能替代调用者授权。实现：

1. Core RPC 分派增加由传输层生成的调用者上下文。
2. 请求正文中的 `approved`、`trusted`、`actor` 等字段不能生成该上下文。
3. Tauri 启动 Core 时使用私有 stdin 引导管道传递临时宿主认证材料；关闭引导管道后正常运行。
4. 认证材料由系统安全随机源生成，只保留在原生宿主和 Core 内存中。
5. Core 重启时重新生成，旧令牌失效；不写 URL、普通日志、SQLite 或模型环境。
6. 原生确认命令仅接受限定动作、请求 ID、版本及当前预览摘要，不提供任意 RPC 转发。
7. 工作台可信 WebView 才能调用；内置网页和插件不能调用。
8. 陪伴窗口需要付费角色确认时，转到工作台完成，不能获得工作台全部敏感命令。

新增确认覆盖预算、合入、撤销，以及本轮接触的持续日程授权和权限扩张入口。旧路径同步纳入，不能保留一个只检查 `approved=true` 的备用入口。

无受管认证的外部 Core 可保持明确的只读诊断；敏感写操作返回需要可信宿主。测试通过显式构造可信测试适配器，不增加 HTTP 参数开启的信任后门。

安全保证限定为应用与受管执行接口边界，不声称防御已完全控制当前操作系统账户的攻击者。

### H03：统一受控模型调用与费用恢复

**对应：R02、R13、R14a。依赖：H02-F，不依赖延期的 H02-U。**

首版使用验收通过的 `0.1.1-rc.2` 固定组合。下面的中立接口、调用状态机与授权设计不因暂缓内核升级而删减；无需先迁移新版 Remote 协议，也不要求先补齐全部模型渠道。

#### 固定路线

```text
DSH原生循环
 → DSH公开LlmAdapter
 → Core受限模型调用入口
 → 既有Provider与费用账本
 → 结构化结果返回DSH
```

DSH 不运行另一份 Sumika API 工具循环。Core 不复制 DSH 会话引擎。

#### 接口与权限

在现有 Core HTTP 服务增加独立受限路径：

- `POST /internal/runtime-model/v1/calls`
- `GET /internal/runtime-model/v1/calls/{operation_id}`
- `POST /internal/runtime-model/v1/calls/{operation_id}/cancel`

该入口只处理模型调用、状态与取消，不暴露用户确认、任意文件访问或整个 Core RPC。

调用绑定由 WorkService 在有效授权下建立，包含工作请求版本、用途、候选、运行实例、调用次数和上限。

受管 DSH 只持有短期执行连接凭据：

- 不能调用宿主确认接口。
- 不能修改候选、目标、预算或授权范围。
- 不包含真实上游 API Key。
- 不进入模型工具参数。
- 子进程环境必须剔除连接凭据。
- 任务结束或启动实例变化后失效。

不根据“最近活跃会话”、提示词或标题猜测费用归属。辅助调用缺少可验证归属时直接阻断。

旧版 loopback HTTP 不构成可信授权。工作绑定必须关联具体请求版本、运行实例、会话和执行步骤，不能只凭 `sessionId` 接纳新调用；直接调用旧入口、伪造会话字段或批准回复不得绕过 Core 消费与工具授权。此边界在 H03 实际发送/执行前验证，不能把 H02 的模型 fixture 当作已完成。

#### 协议转换

采用公开 `registerAdapter`、`prepareCall` 和流式接口，版本细节集中于 DSH 插件。

Core 抽出既有 Provider 的单次受控调用能力，供 API 开发与 DSH 复用：

- 保留结构化 messages、tools、调用 ID、回执和推理续轮字段。
- 完整校验后执行工具，不执行残缺 JSON。
- 保留 usage、结束原因、截断及部分响应事实。
- 不支持的多模态或 replay state 发送前明确拒绝。
- 单次调用结果使用独立回执，不在并发情况下读取其他调用覆盖的 `last_usage`。

#### 费用状态机

每个操作使用稳定 `operation_id`：

```text
intent
 → work-reserved
 → funding-reserved
 → dispatching
 → completed / definitely-not-sent / unknown
```

固定含义：

- `dispatching` 必须在真正发送前持久化。
- 崩溃发生在该标记之后、确定回执之前，一律不能自动重发。
- 只有宿主证明未发送才能释放相应预留并重试。
- 重复操作 ID 加相同输入返回原状态；不同输入拒绝。
- 结果、费用回执和恢复阶段保存后才能进入后续派发。

**现有工作预算、资金及资源记录不是同一数据库事务。** 本轮使用现有各账本加可恢复关联，不声称跨库原子提交：

1. 先持久化工作操作意图。
2. 各账本用同一操作派生 ID 幂等预留。
3. 将所得预留引用记录到工作操作。
4. 全部准备完成才进入 `dispatching`。
5. 中断恢复按引用查询；只对确定未发送的准备失败做补偿释放。
6. 查询不清楚的预留保留，不靠超时或余额变化猜结算。

不新建第三套总账。

#### 防止重复计费

- 外部任务总预算是授权范围，不能作为一笔实际支出再叠加逐调用费用。
- 父子授权共享占用，但物理上游调用只结算一次。
- 预算占用、usage 推导费用和真实账单分别显示。
- 旧 `conservative-upper-bound-not-bill` 数据保持其语义，不批量改写成实付。
- 使用现有精确金额类型和资金分类；已购资源不当免费。

#### 费用边界

- 不继续用无依据的 `high/4`、`high/2` 冒充低位和通常估算。
- 无统计依据时低位、通常显示未知。
- 硬上限必须覆盖实际输入、工具 schema、输出、推理和收费规则。
- 通用“字节数加常量”只能在有适用依据时使用，不能证明所有模型的上限。
- 无可靠上界的付费路径保持不可自动派发。
- 免费证据失效不回退现金。

规划、压缩、重试、验证、标题等辅助用途全部纳入。首版关闭不必要的自动模型标题和无法受控的内部重试。

子 Agent 无法证明授权继承和费用归属时，在受控组合中禁用；不复制第二套子 Agent 引擎。

验收：未授权零发送；辅助用途入账；重复连接不重发；跨库中断可核对；迟到回执不重复结算。

### H04：安全恢复与有界上下文

**对应：R03。依赖：H03。**

#### 公共入口

扩展现有只读 `work.task.inspect`，增加：

- `work.task.resume`

继续现有 SDK，增加版本化执行 checkpoint：

- 保存当前阶段、下一个操作位置、必要消息或受控内容引用、工具配对、已验证成果。

- 回执、checkpoint 与内容关联由宿主提交，不把“输出已到达但尚未持久化”视为安全完成。
- 旧记录没有 checkpoint 时只提供检查，不能猜测重建。

| 情况 | 行为 |
|---|---|
| 明确未发送且授权仍有效 | 可以接续 |
| 已完成且结果持久化 | 使用已有结果 |
| 模型提交未知 | 只核对，不重发 |
| 工具副作用未知 | 检查真实文件、进程与回执 |
| 工作副本或输入来源改变 | 使相关验证失效，重新预检 |
| 取消后迟到结果 | 更新事实，不重新启动任务 |
| 候选或运行绑定改变 | 不静默恢复到新模型/Harness |

首次启动恢复默认只读检查，用户触发恢复后才派发。范围和费用没有变化时，不重复要求原有授权。

验收包含模型发送、写文件、运行测试、结果持久化前后故障注入；未知操作不得通过修改需求版本清空。

### H05：源码一致性、验证与安全合入

**对应：R01、R03c、R05。依赖：H01；最终整合依赖 H04。**

#### A. 源码准备

- 预检说明纳入和排除范围。
- 确认后捕获文件清单、字节摘要和相关属性。
- 复制后重新检查来源，发生变化则停止该次准备。
- 关键文件复制失败不能静默跳过后声称完整。
- 保留原仓库 staged、unstaged、untracked 状态，不自动提交。
- 同一套安全路径处理覆盖中文、空格、大小写、ADS、设备路径、链接、junction、reparse point 和 hardlink。
- 不以字符串前缀或一次 `resolve()` 代替完整检查。

工具环境由宿主显式注入，去除通用执行器内 Sumika 专用环境硬编码。

源码副本和 Job Object 不构成 OS 沙箱。首版仍是用户已授权的本机执行模式，不能宣称阻断测试代码的全部文件或网络访问。

#### B. 独立验证

- 宿主冻结验收定义及摘要，执行者不能以修改自身测试的方式替换验收依据。
- 记录源码、测试命令、验收文件、相关依赖和环境。
- 在独立验证副本运行固定验收。
- 测试修改受检源码、删除冻结验收或缺少必要测试时，不给出通过结论。
- 区分执行者自测、宿主验收和用户审查。
- 需要模型审查时进入预算，不固定为所有任务增加贵模型调用。

#### C. 文件合入接口

新增：

- `work.task.merge.preview`
- `work.task.merge.apply`
- `work.task.merge.undo.preview`
- `work.task.merge.undo`

所有写操作通过 H01 的可信确认入口。

首版支持普通文本文件的新建、修改、删除；普通重命名按删除与新建共同预览。二进制、链接、特殊文件和 Windows 仅大小写重命名明确拒绝。

固定冲突策略：

- 无关文件变化保留。
- 受影响文件不同于预览基线，直接报告冲突。
- 首版不自动三方合并，避免由低推理执行阶段决定冲突取舍。

#### D. Windows 写入安全

优先保证不覆盖未经审查的用户修改及中断可恢复，不承诺跨文件原子事务。

操作顺序：

1. 生成并确认预览。
2. 对源仓库的合入操作串行化。
3. 使用稳定文件句柄核验目标身份、类型、链接和内容。
4. 在校验与写入期间保持必要的并发保护，不能关闭句柄后无条件覆盖。
5. 保存 before-image 和事务意图。
6. 新文件使用排他创建；现有文件在受保护句柄上修改；删除按已核验文件身份执行。
7. 每条路径更新事务结果。
8. 崩溃后根据日志和真实内容检查，不能默认整批成功。

不能取得可靠保护时返回明确限制，保留 patch，不换成不受控覆盖。

部分写入后若内容既不匹配 before，也不匹配 after，保留现场并等待检查；不能以自动回滚名义覆盖可能存在的用户新改动。

撤销只恢复仍匹配本次 after 状态的路径；用户后来修改过的路径形成冲突。

验收：脏仓库、双任务竞争、预览后变化、链接替换、写入中断、撤销前编辑及 index 保持。

### H06：开发路径整合与首次真实闭环

**对应：R07a/b、R17。依赖：H00、H01、H02-F、H03–H05；不依赖 H02-U。**

#### 执行整合

- 复用现有 Quality 派发及 Agent 适配。
- 为 DSH 开发任务提供薄开发适配器，负责源码副本准备、会话绑定、事件转换和成果引用。
- 该适配器调用 DSH 原循环，不调用 SDK 的 API 工具循环。
- 既有 API 执行器保持显式可选路径，不自动替换运行任务。
- 同一工作请求经过旧准入适配器时复用已有授权和调用引用，不产生第二笔整任务费用。
- 主 Agent 的节点交接通过 H00 检查后再进入实际开发执行。

允许为确认、检查、恢复和合入做最小 UI 接线；不在此包完善整个工作台。

#### 验证层级

1. 离线 SDK 和本地 HTTP stub。
2. 真实 DSH、真实工具与临时仓库，模型使用可声明 fixture。
3. 获授权真实模型经 Sumika 完成一次小范围源码修改。
4. 独立构建和运行验收。
5. 用户审查具体 diff 后执行受控合入。

真实自改必须由 Sumika 中运行的模型完成修改。外部 Codex 写好代码再交给 Sumika 展示不算成功。

选定真实任务后，使用主 Agent 已验证的能力与固定验收。免费合格就用；付费需要准备明确上限，已有余额不构成本轮无限测试授权。

独立测试版使用独立输出、端口和数据，不覆盖日用可执行文件或迁移登录档案。

缺少真实候选、付费授权或必要普通 UI 时，完成其他高难工作及准确恢复说明；不能冒称已通过真实闭环。
