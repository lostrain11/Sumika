# 可复用组件边界

状态：规划中。完成度只看[状态矩阵](../status-matrix.md)的`reusable-components`；本文不把已有 SDK、DSH 桥接或 manifest 标为已独立发布。

本规范实现`PLUGIN-003`，详细任务顺序和验收场景见[客户端工作流 v2](../refactor/client-workflow-v2.md)。它扩展而不取代`PLUGIN-001`、`PLUGIN-002`、`AGENT-001`及现有质量路由实现。

## 目标

可复用功能由小型核心、宿主适配器和装配入口组成：核心不导入 Sumika 应用对象、Tauri、前端全局状态或 Sumika 私有数据库；适配器依赖核心契约；装配入口将具体实现注入核心。共享进程、数据库或基础库是允许的明确依赖，不以“独立”为名复制算法、隐藏耦合或新建泛化插件平台。

```text
Sumika client and composition root -> Sumika adapter -> reusable core
DSH host -> DSH adapter -----------------------------> reusable core
CLI/MCP/other Harness -> adapter --------------------> reusable core
```

核心只接收实际需要的版本化数据对象和窄接口，例如候选/质量证据、报价、资金预留、执行、验证、用户授权、存储、时钟、取消信号和事件通知。报价、预留和实际结算是不同步骤；凭据仍由宿主受控执行器持有，不能透传给模型工具或核心数据对象。

## 宿主边界

| 层级 | 拥有内容 | 禁止内容 |
| --- | --- | --- |
| 核心 | 任务契约、候选选择、预算规则、DAG、验证、升级和能力声明 | 导入 Sumika `CoreApplication`、Tauri、前端状态、私有数据库实现或具体宿主适配器 |
| 适配器 | 用户确认、模型/工具执行、任务存储、浏览器、时钟或窗口等宿主能力转换 | 复制核心算法、绕过授权、把宿主全局状态传入核心 |
| 装配入口 | 选择并连接具体实现，声明能力、生命周期与数据目录 | 以大而全的 `HostContext` 重新隐藏耦合 |

缺少能力时返回明确不可用；不隐式读取 Cookie、凭据、个人文件或调用付费服务。外部宿主与 Sumika 必须调用同一份核心代码，现有 `dsh-route-bridge` 仅作为仍依赖 Sumika 的兼容桥接，不能据此声称独立。

## 独立验收

组件只有同时满足以下条件才可标为独立复用：

1. 在干净环境仅安装组件和声明依赖即可加载、启动、停止与卸载。
2. 不启动 Sumika Core 或 Tauri，不读取 Sumika 私有数据库、配置或运行数据。
3. 声明输入、输出、错误、能力和生命周期，行为测试、示例、版本与许可证齐备。
4. 至少在一个独立 CLI、MCP 宿主或其他 Harness 运行，能力缺失明确失败。
5. 发布物不包含个人模型、运行数据、账户快照、凭据或秘密。

浏览器、GPU 和窗口可以是声明能力，但必须通过适配层连接。离线执行器示例只能证明生命周期和宿主适配，不能冒充真实模型质量验收。

## 首个示范

首个候选是现有`packages/quality-routing`。P02 将提取仍混在协作服务中的通用工作流和证据接口；P09 再验证独立安装、离线完整生命周期和可选 MCP/DSH 薄适配。Sumika 人格、页面、当前应用配置及 Provider 凭据保持在适配器；不建立第二套调度器、报价或余额账本。

本轮其余模块只按同一边界预留：项目与上下文、长期记忆、定时工作、浏览器策略、Avatar/场景和窗口管理。未通过本节独立验收前，状态保持规划中或保留其既有实现状态。
