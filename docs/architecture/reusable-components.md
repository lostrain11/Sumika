# 可复用组件边界

## 本轮增补契约

[最终执行计划](../refactor/harness-portability-hard-tasks-v1.md)固定AGENT-003和WORK-002：增强核心依赖中立窄接口，DSH为默认薄适配器；稳定profile实例和每次启动身份分离。更换Harness只影响后续请求，跨Harness续接重新预检，不搬凭据、私有transcript或消费授权。交接检查采用现有SDK任务快照旁挂元数据，不新建调度器或数据库。复杂生产任务的强制检查由宿主设置；滚动图结束仍有阶段时返回needs-planning。以上为本轮实施契约，非完成声明。

状态：规划中。完成度只看[状态矩阵](../status-matrix.md)的`reusable-components`；本文不把已有 SDK、DSH 桥接或 manifest 标为已独立发布。

本规范实现`PLUGIN-003`，详细任务顺序和验收场景见[客户端工作流 v2](../refactor/client-workflow-v2.md)。它扩展而不取代`PLUGIN-001`、`PLUGIN-002`、`AGENT-001`及现有质量路由实现。

## 目标

可复用功能由小型核心、宿主适配器和装配入口组成：核心不导入 Sumika 应用对象、Tauri、前端全局状态或 Sumika 私有数据库；适配器依赖核心契约；装配入口将具体实现注入核心。共享进程、数据库或基础库是允许的明确依赖，不以“独立”为名复制算法、隐藏耦合或新建泛化插件平台。

```text
Sumika client and composition root -> Sumika adapter -> reusable core
DSH host -> DSH adapter -----------------------------> reusable core
CLI/MCP/other Harness -> adapter --------------------> reusable core
```

核心只接收实际需要的版本化数据对象和窄接口，例如候选/质量证据、报价、资金预留、执行、验证、用户授权、存储、时钟、取消信号和事件通知。报价、预留和实际结算是不同步骤；凭据仍由宿主受控执行器持有，不能透传给模型工具或核心数据对象。

## 上游优先，差量实现

用户已确认：现有开源 Harness 能力应先核验、优先复用；Sumika 当前以 DSH 为生产 Agent Runtime，优先参考并适配固定版 DSH，Codex 开源 CLI/app-server 作为补充和成熟实现对照，不以此默认更换底座。Codex 开源组件不等于其桌面客户端所有功能均开源。

每个新增或重构子包在写通用机制前，先检查本地已有实现、固定版 DSH 的实际源码/API，再针对缺口检查 Codex 或其他合适组件。顺序为：**现有能力直接调用 → 薄适配 → 合法提取可独立部分 → 必要差量实现**。不是每个小修都要重做选型；同一版本、同一边界复用已有核验记录。

- 在任务所属现有专题内记录来源版本/commit、实际接口、依赖和许可证、选择方式、未复用原因及验收缺口；不能仅凭名称、README 或“提供恢复”就推断语义相同。
- DSH 路径的会话、工具进程和上下文由 DSH 管理，Sumika 持来源引用及预算/授权映射，不另建同功能引擎。现有 API 直连开发路径不经过 DSH，不因 DSH 已有插件就宣称直连路径也具备其能力；复用需明确协议、生命周期和接线成本。
- 原生模型循环、压缩、恢复、执行审批、文件修改与沙箱均优先借用上游成熟能力。不为“独立复用”造完整 Harness，不因现成实现成熟而强行引入第二套会话、运行时和数据库。
- Sumika 保留最终身份、权限、消费授权、共享资源预留、结算和未知提交策略。上游已恢复会话不证明调用未发送、账单已结算或可以重发；自动压缩/总结若调用模型同样需要费用授权。
- 复制/修改第三方源码前核验该文件及依赖许可证，保留适用版权、LICENSE/NOTICE、变更及来源记录。仅借鉴机制与直接复制分开说明。未做真实集成不能标为已复用或通过验收。
- 上游版本变化先做隔离契约回归，不隐式升级日用 DSH、Codex 或改其个人配置；没有必要不扩展第二 Harness 生产适配。

首轮源码核验及本次保留实现理由见[开发恢复：上游对照](development-recovery.md#上游对照与复用决策)。本节约束后续 R01–R07 及其他可复用模块，不降低既定权限、费用与分发验收。

### 独立增强层与薄适配器

对于参考或复用 Harness 后新增的能力，优先采用组合而非修改上游内部：

```text
Sumika UI / other host UI
    -> host composition and trusted authorization
    -> reusable extensions (policy, budget, projects, artifacts, recovery reconciliation)
    -> narrow Runtime contracts
    -> DSH adapter -> pinned DSH
    -> optional Codex adapter -> Codex app-server
    -> existing direct API adapter -> bounded development executor
```

增强核心承载可跨宿主复用的产品规则；薄适配器只翻译请求、事件、能力声明和错误；Sumika 装配入口提供受控凭据、存储、确认界面及执行资源。不能把业务规则全塞进单个 adapter，也不能让核心读上游内部私有状态。这个目标不表示当前 `WorkService` 已可独立安装或 Codex adapter 已接入。

每条任务路径只选一个执行/会话所有者，增强层持外部 ID 和授权映射，不复制上游 transcript、工具循环、压缩器和进程管理。Runtime 的原始事件经窄接口供增强层核对，只有已确认事实可以更新费用、成果或恢复状态；增强层不能伪造上游完成、把取消响应当结算或自行重发未知请求。

上游必须提供的前置检查、取消、事件或可靠状态读取若缺失，适配器明确声明不支持，不能靠包装声称可强制硬上限。先考虑已有公开扩展点或最小上游补丁；确需 fork 时另记补丁、许可、升级代价及回归，不以复制整仓作为默认办法。已写的 API 路径作为显式可选实现逐步整合，未经替代验收不删除现有可用功能。

## 宿主边界

| 层级 | 拥有内容 | 禁止内容 |
| --- | --- | --- |
| 核心 | 任务契约、候选选择、预算规则、DAG、验证、升级和能力声明 | 导入 Sumika `CoreApplication`、Tauri、前端状态、私有数据库实现或具体宿主适配器 |
| 适配器 | 用户确认、模型/工具执行、任务存储、浏览器、时钟或窗口等宿主能力转换 | 复制核心算法、绕过授权、把宿主全局状态传入核心 |
| 装配入口 | 选择并连接具体实现，声明能力、生命周期与数据目录 | 以大而全的 `HostContext` 重新隐藏耦合 |

缺少能力时返回明确不可用；不隐式读取 Cookie、凭据、个人文件或调用付费服务。外部宿主与 Sumika 必须调用同一份核心代码，现有 `dsh-route-bridge` 仅作为仍依赖 Sumika 的兼容桥接，不能据此声称独立。

## 独立验收

组件只有同时满足以下条件才可标为独立复用：

1. 在干净环境仅安装组件和声明依赖即可加载、启动、停止与卸载。
2. 不启动 Sumika Core 或 Tauri，不读取 Sumika 私有数据库、配置或运行数据。
3. 声明输入、输出、错误、能力和生命周期，行为测试、示例、版本与许可证齐备。
4. 至少在一个独立 CLI、MCP 宿主或其他 Harness 运行，能力缺失明确失败。
5. 发布物不包含个人模型、运行数据、账户快照、凭据或秘密。

浏览器、GPU 和窗口可以是声明能力，但必须通过适配层连接。离线执行器示例只能证明生命周期和宿主适配，不能冒充真实模型质量验收。

## 首个示范

首个候选是现有`packages/quality-routing`。P02 将提取仍混在协作服务中的通用工作流和证据接口；P09 再验证独立安装、离线完整生命周期和可选 MCP/DSH 薄适配。Sumika 人格、页面、当前应用配置及 Provider 凭据保持在适配器；不建立第二套调度器、报价或余额账本。

本轮其余模块只按同一边界预留：项目与上下文、长期记忆、定时工作、浏览器策略、Avatar/场景和窗口管理。未通过本节独立验收前，状态保持规划中或保留其既有实现状态。
