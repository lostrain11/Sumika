## 2. 信息架构

顶层五入口：**陪伴 / 工作台 / 能力 / 角色（预留 P6）/ 设置**。未实现功能一律虚线占位、明确标注阶段号、不可开启（P5：OCR·截屏翻译、桌面软件控制、内置浏览器；P6：角色卡、多角色、Live2D/VRM、长期记忆、语音；P7：桌宠、壁纸陪伴）。

三方向差异仅在导航形态与视觉语言：

- **A · 澄空茶室**：顶部分组导航 + 三栏工作台（项目/会话侧栏 · 时间线 · 陪伴栏）。浅色和风，继承旧版 workbench-v2 气质。
- **B · 星轨观测所**：左侧图标轨 + HUD 顶条。暗色科幻，能力页为星座图，状态反馈（辉光、等宽数字）最强。
- **C · 放课后活动部**：房间即界面（书桌→任务板、公告板→任务板、书架→能力、门→设置），暖色漫画描边风，隐喻统一、学习成本最低。
- **D · 晴日部室（2026-09-14 追加）**：沿用 C 的「房间即界面」隐喻，视觉改为旧版清爽日系（米白 / 墨绿 / 玫红 / 水色，细描边、大留白、柔和阴影），面向标准头身日漫 VRM 模型；左侧「部员名册」演示多角色排布与切换。C 的粗描边 Q 版漫画风与该类模型风格冲突，D 为其替代候选。工作台采用 **Codex/ZCode 式布局**（左侧「项目 ▸ 任务」树状侧栏 + 中央会话时间线 + 底部输入框），任务作为项目子项嵌套、项目可折叠、已归档收起，更贴合编码工作流；看板泳道式任务板已弃用。**视觉语言已与旧版 workbench-v2 中和**（2026-09-14 评审决定）：顶栏改为旧版式文本导航 + 激活项底部 3px 玫红条，全局圆角收敛至 8–9px、阴影减淡、玫红/墨绿向旧版 #a94067/#47746a 靠拢、侧栏激活项改为旧版式「淡底 + 1px 边框」；能力页保留 D 的卡片模块与图标体系不变。**功能范围以 approved-plan 为准**：仅出现 P0–P7 计划内功能（明确不做的自动选模、复杂费用路由、免费权益、macOS/Linux 支持不出现）；本次对齐补齐计划内缺失的「定时任务（P5）」「角色卡 · 世界书（P6）」两张预留卡，模块计数 8 启用 / 8 预留 / 共 16。

**导航原则（2026-09-14 评审决定）**：功能入口唯一权威 = 顶栏全局导航，与场景无关；**场景物件仅为陈设，不绑定任何功能**——角色随自主活动切换场景（书房 / 卧室 / 厨房…）后，房间内容物会变化，功能可达性不受影响。C 的「物件即入口」绑定方式随之弃用（C 仅保留为视觉风格候选）。方向 D 已按此实现：顶栏 活动室 / 工作台 / 能力 / 设置 常驻，房间内公告板、书桌、书架、挂钟均为纯陈设。

### 陪伴呈现层级（依据用户使用频率：工作台为主，陪伴页最少用）

- **L0 · 桌宠小窗（默认陪伴形态，方向 D 已实现原型）**：应用内全局浮动小窗，**可自由拖动到任意位置**、跨页常驻（工作台 / 能力 / 设置页均可见），进入陪伴页时自动隐藏（避免与镜头窗口重复）；可收起为头像圆点。状态与任务联动（执行中→「书房 · 工作」）。**小窗下方附带迷你聊天框**：非陪伴页场景下的主要闲聊入口，可随意对话、看她按当前活动状态（待机/工作/休息）切换语气的吐槽与进展播报（原型为模拟回复，后续接入真实对话流）。小窗操作行只保留「收起」——取景切换与「放大」入口均已下线，因为放大与顶栏「回活动室」语义重复，而 L0 的定位本就只有一个全景视角。
  - **聊天气泡：默认收起、悬停展开（2026-09-14）**：气泡常态只露**最近三条**记录（用 `:nth-last-child(-n+3)` 精确控制条数，而非按像素高度裁切——消息换行时按高度裁会出现「只露两条 / 第二条被切一半」的不确定结果）；**鼠标悬停即展开**为完整可滚动记录，移开自动收起；**点击可固定展开**以便从容翻阅更早内容（提示文案在「点击收起记录」与「悬停展开 · 最近 3 条」间切换）。气泡采用**向上生长的绝对定位**（挂在取景框行的上边缘之上），因此展开时不会推挤下方取景框、小窗总高度不变，鼠标在气泡与取景框之间移动时不会因布局跳动而抖动。切换活动状态时，她会把当前状态当作最新一条消息播报进记录，使收起态的最近三条始终是新鲜的。
  - **小窗呈现「角色在场景中的视角」（2026-09-14 实现）**：小窗内容不是一张人物特写，而是**看向她所在房间的一段取景**——能看到她此刻站在房间里的位置，以及其周边的墙面、地板与陈设（书桌 / 书架 / 绿植）。取景随活动状态切换**三个不同机位**（待机 / 书房工作 / 休息），构图明确区分，一眼能看出她换了地方。
  - **实现要点（可复用于 P7 独立窗口）**：小窗以「克隆的房间」作为世界画布（2D 背景 + 3D 陈设），并在其中放置**小窗专属的 VRM 渲染容器**独立挂载一个渲染实例——因为 `<canvas>` 无法被 `cloneNode` 复制（只会得到空白节点），小窗必须拥有自己的实例；渲染器按容器元素登记实例（内部 `WeakMap`），原生支持多实例。这正是 P7「透明置顶独立窗口」的同一条路径，届时只需把该容器搬到独立 OS 窗口。取景以「世界坐标平移取景窗」实现（非缩放整屋）：世界坐标系固定为舞台的 888×836 CSS 尺寸，角色锚点由克隆体内元素 rect 反推后再加构图偏移（偏移量而非写死世界坐标，模型换人 / 换高矮可自适应）。VRM 渲染器的透视相机不可调（`mountVrmViewer` 仅暴露 `naturalPose` / `roomEnabled` / `vrmaSource` / `vrmaLoop`），故「推近」只能靠收窄取景窗实现。
  - **两条关键渲染约束（2026-09-14 实测，务必保留）**：① **VRM 画布必须保持透明**——渲染器以 `alpha:true` + `setClearColor(0, 0)` 创建上下文，画布本身透明；此前为「统一房间色调」给画布刷了不透明渐变底色，结果在取景框里贴出一块纯色板，把整间房全盖住，小窗退化成「大头照相框」。保持透明后，房间从画布后透出，人自然站进房间里——**房间色调应由房间自身图层（`.stage` 的 CSS 渐变）统一，不要覆盖到画布上**。② **隐藏占位立绘的 CSS 选择器必须覆盖克隆体内所有层级**——初版只写了 `.dp-scene .vport .chara-svg`，一旦角色层的类名被 `.pos-work` / `.pos-rest` 改写、或立绘被放进更深一层，规则即失配，小窗会同时出现「占位立绘 + VRM」两个角色。应以 `#deskpet[data-vrm="on"] .dp-scene .chara-svg` 这类兜底写法覆盖。

- **L1 · 陪伴页镜头窗口**：沉浸式全屏房间画面，用于专门陪伴，使用频率最低。
- **L2 · 独立桌宠窗口（P7）**：透明置顶 OS 窗口，挂在游戏 / 视频等其他应用之上——即 L0 的独立窗口化。
- **L3 · 全屏壁纸陪伴（P7）**：Sumika 全屏挂为动态壁纸，角色在壁纸级房间中生活。

### 多角色扩展设计（针对方向 C/D 的评审提问）

- **数据契约先行**：角色 = 角色卡（id、名称、头像、VRM/Live2D 模型绑定、强调色、口吻模型绑定、独立记忆命名空间）。UI 一律绑定「在场角色」（activeCharacter），不写死角色名；方向 D 原型已按此演示（名册点击切换，名牌 / 气泡色条 / 发送键 / @chip 跟随）。
- **排布三层**：① 名册 rail——纵向成员列表，活跃角色置顶，≥6 人折叠为头像列，导入入口固定在末尾（P6）；② 舞台——「镜头窗口」：陪伴屏是看向角色自己房间的镜头画面，对应 P7「虚拟房间、固定或跟随摄像头视角、自主生活」；角色在房间内自主活动（待机 / 书房工作 / 休息），执行任务时坐到书桌前使用电脑，镜头可跟随、固定或特写；次要角色以小站位 / 半透明灰度占位（多人同屏 P6）；③ 对话流——气泡按角色强调色着色 + 名字标签，支持 @ 提及切换。
- **渲染分层（性能方案，方向 D 已标注）**：① 背景 2D 图片（墙 / 窗 / 地板）；② 关键物件 3D 建模（电脑桌、电脑椅、显示器、键盘等可交互物件）；③ 角色 VRM/Live2D。全 3D 场景性能成本高，混合渲染是用户认可的折中；原型中以图层图例与「3D 占位」标签明示分层。**VRM 实机渲染已验证（2026-09-14）**：方向 D 直接复用旧版 `frontend/public/vendor/sumika-vrm-viewer.js`（three.js + @pixiv/three-vrm 打包，含自然站姿、呼吸/眨眼、视线跟随、离屏暂停）挂载官方示例模型 AvatarSample_A（VRoid 标准头身日漫模型，安和昴同型渲染链路，许可台账见 assets/README.md）。演示绑定在名册「昴 · 示例角色卡」：切到昴 = 实机渲染（含活动位移/镜头推拉），其余角色 = 立绘占位；桌宠小窗同步挂载**独立 VRM 实例**呈现真实模型。验证了「UI 绑定在场角色、角色卡携带 VRM 绑定」的数据契约可落地。
- **房间风格需与模型风格匹配（2026-09-14 修正）**：房间基调改为**暖调奶油墙面 + 木色地板**（含墙裙线、地板拼缝、暖色光斑），窗与窗帘、家具一并转为暖木色系——原先的冷白 / 灰调房间与暖色系日漫 VRM 模型（肤色偏暖、发色偏棕）并置时割裂感明显。设置页背景项相应更新为「邮漫午后」。**注意：色调统一应通过房间自身的 CSS 图层实现，不要给 VRM 画布刷底色**（刷底色会遮住整个房间，详见 L0 的渲染约束）。
- **切换语义**：切换只换「在场角色」，不打断工作台任务；每角色独立会话上下文与记忆命名空间。
- **配色策略**：角色强调色仅渗透小面积元素（名牌、气泡色条、chip、发送键），全局主题色不变，避免多角色配色互相冲突。
