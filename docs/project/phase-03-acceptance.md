# 阶段 3：Codex 日用开发平替

状态：完成。实现、真实开发、审查、压缩后重启恢复与整合验证均通过。

## 实现范围

- `sumika run` 启动固定版本的受管 DSH 原生 Web，默认使用独立版本 profile。`--workspace` 经统一授权入口登记原生工作区并创建会话；工作区返回值、会话目标与实例绑定须一致。省略工作区时恢复原生历史，不自动发起模型任务。
- 工作区、会话、Plan、执行、搜索/读写/删除、终端、测试、日志、Skills、MCP 和子 Agent 复用 DSH。暂停语义为取消当前工作并保存交接，恢复先核对历史和实际改动；不声称进程冻结或回滚副作用。
- `sumika receipt --input <项目内JSON>` 显式记录任务成果、会话、Git HEAD、UTC 时间、验证结果、未完成项和下一步；独占创建，不覆盖旧记录。`check` 校验记录，`handoff` 追加最近三条。
- 记录标明 `operator_report`；passed/failed/not_run 是操作方声明，不自动升级阶段状态，也不增加授权。需求原文和成果正文不被摘要覆盖。
- 项目 `AGENTS.md` 指向现有连续性记录，压缩/重启后重新读取。日常用法见 `daily-workflow.md`。自动捕获和会话接线仍属于 P4。

## 真实开发验收

使用用户授权的测试凭据、DeepSeek 官方 provider 的 `deepseek-flash`（原生 UI 显示 DeepSeek-V41-Flash，High），在从新版分支干净克隆的隔离项目中实现 receipt 功能。旧源码、日用 profile 与其他项目不参与实现。

过程包括原生 Plan 计划审阅、代码阅读和修改、完整测试、真实 CLI 示例、原生子 Agent 两轮独立审查、修复以及主 Agent 整合。子 Agent 实际发现空 session_id 写读不对称、编码失败留下空文件等问题，开发 Agent 修复后再次验证。主 Agent另补 Windows 保留文件名、单条记录读取不得越界、写失败不删除未由本次创建的路径，以及阶段推进后仍有效的测试。

此前两次凭据被官方端点以 401 拒绝，未计为模型工作成功。之后有效测试凭据完成真实任务；未使用其他云端提供方或自动付费 fallback。

- 构建 wheel 成功；P2 发行/认证/工具/Plan/取消/恢复门槛重跑通过。

## 限制与回退

- 一次真实项目任务证明本次闭环可用，不代表所有任务、模型或第三方插件的质量与兼容性已穷尽。
- 原生 Windows 沙箱沿用上游 partial enforcement 边界；Plan 是规划/审阅交互，不将其称作独立 OS 只读沙箱。
- 当前会话的暂停由取消+交接实现；未知结果不得自动重放。没有增加凭据管理器、模型路由器或自建 UI。
- 一项符号链接用例受系统权限限制未实测；已验证普通路径穿越与目录联接边界，其余限制不隐藏。
- 回退同时恢复对应 Git 提交及 profile 备份，保留当前数据；不得原地降级 profile。测试凭据不提交，临时副本测试后移除。
