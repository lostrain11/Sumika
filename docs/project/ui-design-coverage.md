**明确否决过的实现方式**：不 fork DSH 前端、不 iframe 内嵌 DSH 应用（工作台这一屏本身就是 DSH，见 `workbench-skin-plan.md`）、不新增与既有入口重复的导航（能力、项目面板均已删除，`tools/verify_dsh_panel.mjs` 反向守卫）。

**待用户决策（阻塞侧栏还原）**：设计稿的行内信息（路径、计数、状态点、"状态 · 时间"）与常驻搜索框，无法只靠 CSS 表达。两条路：

**用户已选路线 2（保留原生浏览器，2026-09-16）**，因此侧栏按"皮肤上限"收口，实测结论如下：

| 设计稿元素 | 皮肤能否做到 | 依据 |
| --- | --- | --- |
| 新建任务按钮（玫红实心） | ✅ 已做到 | `_newSession` 是语义后缀 |
| 任务行圆角/悬停/选中态 | ✅ 已做到 | `_sessionRow` / `_selected` |
| 任务行圆角方块状态点 | ⚠️ 仅"有状态时" | 该点由 DSH 按真实状态渲染；无状态的行不画点，避免编造状态 |
| 项目行（圆点 + 名称 + 路径 + 计数 + 折叠箭头） | ❌ 做不到 | 工作区行是基础件 `*.root` span（`_root_1b2ny_3`），无语义后缀可锚；路径/计数 DSH 根本没渲染 |
| 任务行"状态 · 时间"文案 | ❌ 做不到 | DSH 只渲染相对时间，状态词未渲染 |
| 常驻搜索框（"搜索项目与任务…"） | ❌ 不做 | 输入框虽在 DOM 里，但 DSH 只有点击搜索按钮才会进入 search 状态并**抢焦点**；仅用 CSS 显示出来会得到一个点了没反应、打字不搜索的假控件 |
| 侧栏页脚状态块 | ✅ 已做到 | 我们自己的 `sidebar.footer.action` |
| 顶栏/侧栏底色、圆角、滚动条 | ✅ 已做到 | 皮肤令牌 |

结论：皮肤路线能把侧栏带到"配色、按钮、行态、页脚"一致，但**行内信息（路径/计数/状态词）与常驻搜索框必须换渲染方**才能达到设计稿。若后续仍想要这部分，需要回到路线 1（接管 `sidebar.workspaces`）。

1. **接管 `sidebar.workspaces`**（`priority: -1` 顶掉原生 WorkspaceBrowser），由 Sumika 用真实工作区/会话数据渲染设计稿的树 —— 视觉最接近，但必须自己重做搜索、归档、重命名、fork、拖拽排序，否则这些能力会丢。
2. **保留原生浏览器**，只在皮肤层继续微调（当前状态）—— 功能完整，但行内信息与常驻搜索框无法达到设计稿。

在用户选定之前，本项保持"部分照做"，不做进一步改动。
