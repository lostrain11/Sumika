## 1. 目标和资产

用户认为模式是若干设置组合，明确选可自定义＋自动匹配。学习/游戏/安静只是可修改模板，不固定枚举。手动选择一直优先；观察与声音许可独立。R-125已提自动识屏但未实施。

现有companion-session.js的text/voice是交流通道，roles work/role是模型通道，不复用成活动模式。复用contracts、WGC/UIA/OCR、coordinator、budget、现有配置原子保存和revision，不新建游戏owner或采集系统。B站专属适配不能套其他教学网站。

设计稿ui/prototype-d/index.html:937语音卡、957详情、1040附近权限、1063数据区；现有唯一陪学详情在能力页语音交互。新增profile控件没有原设计，用户本轮已确认放现有详情，许可放权限，行为管理放数据；不新主页面/导航。更新覆盖表并逐屏核对，保留DSH原生功能。

## 2. 配置、API和兼容（P14）

个人目录`companion-profiles.json`，CompanionProfileStore独立中立；原子保存、schema_version=1、revision由服务端计算。存坏配置保留供恢复，中性待命，不静默重建/开许可。

```text
ProfileConfig:
  schema_version, revision
  selection_policy: auto | manual
  manual_profile_id: string | null
  profiles: Profile[]

Profile:
  id: stable UUID generated by server
  name
  enabled_for_auto
  scenario_description
  response_instructions
  settings:
    proactive_enabled
    proactive_interval_seconds
    behavior_prompts_enabled
    context_sources: [text, image, application_audio]

Runtime:
  effective_profile_id: string | null
  reason: manual | matched | ambiguous | unknown | suspended
  candidate_profile_id, score
  profile_revision, target_identity, session_epoch, routing_epoch
  unavailable_preferences
```

实施限额：name1～80字，scenario/instructions各最多2000字，profile最多32，启用自动最多16；interval为120～86400整数。context_sources可空且去重，拒绝未知字段。总请求超模型预算明确unavailable，让用户缩短/减少启用项，不悄悄遗漏某些profile。数值限额是本稿实施默认。

settings是期望参考和回应，不是授权。禁止profile携凭据、provider/endpoint、任意配置路径、可执行代码、工具权限、系统命令、自动长期写入开关。response_instructions只能影响角色回复；classifier仅名称/适用场景/用户明确场景关联，不执行response文字。

接口 `/api/manage/companion-profiles`：GET列表/config/runtime；POST action create/update/duplicate/delete/select。写操作expected_revision，冲突409保留UI草稿；请求的profile_id必须存在。create/duplicate新ID，默认auto disabled；用户填描述明确启用。

模板是首次初始化普通数据：学习（教学理解/建议、300秒、behavior开、text/image/app_audio参考），游戏（情境简短吐槽、180秒、behavior开、text/image参考），安静（无主动、无询问、context=[]）。来源可用性仍授权交集，模板不启声音。三模板全可删，不能按名字/ID分支执行。

手动选保存manual+id，跨应用/重启保留至显式auto。编辑当前profile取消旧主动，手动锁保持。删当前手动→manual+null待选择，不偷偷auto；删当前自动→中性，再匹配剩余；删全部合法。null不是不可删第四模板，普通聊天仍可用，无场景主动输出。

首次新用户配置auto建议选项，未许可不开观察。升级旧用户初始化manual学习保持旧行为，不改model/mic/device/multimodal配置；运行旧会话到结束再启新profile，避免热升级改体验。旧一次性同意不能变持久；新明确保存的许可可随启动恢复，替代旧冻结稿“重启一律不恢复”。新target/grant必须重新生成，mic/audio不自动开。

## 3. 自动路由与策略（P15）

### 3.1 三个独立控制

全局观察许可决定能否采集；auto router低频观察负责选择；profile context_sources决定角色参考。安静context为空不关已经授权的router，否则无法退出安静。界面说明安静仍可自动匹配；真正全局停止观察立即suspended并取消分类，不绕过。

manual不运行模型分类；合法输入/行为记录和目标安全检查由各自全局许可控制。角色模型仍按当前配置，无新自动选模。页面内容/模型输出不能改许可或profile。

### 3.2 前台和场景判别

本地前台元数据1Hz；新身份稳定2秒才绑定，切换立即隔离旧context/后台/TTS。窗口PID创建身份、材料、许可revision绑定。自身前台暂停外部发言，不以自身聊天做学习材料；最小化/锁屏/安全桌面/黑帧/撤销即时不可用，不等防抖。

先可靠文本、app/材料/媒体线索；不足且image许可/provider支持才一张缩略图。PDF可能小说，B站可能娱乐；域名/扩展名只是线索。非B站用通用窗口，不扩大扩展host权限。

一次分类比较所有启用profile，只发有界当前材料和场景描述，返回候选ID和有限0～1分数。最高>=0.8且领先第二>=0.15才合格；其余ambiguous/unknown。分数不宣传概率。不存在ID、过期revision/epoch、JSON坏、NaN、超时都unknown，无自动fallback。

候选合格后目标及证据有效持续8秒应用；只一次模型结果，其间本地校验，不强制二次付费。游戏画面运动不代表场景变了。相同未变化场景60秒内最多初次一次模型，同目标重分类至少30秒。材料/视频/页面导航、文本结构实质变化触发，同图像每帧运动不触发。用户提问优先，budget等待中性，不沿用旧目标建议。

目标换材料即时取消旧request；目标相同且场景无实质变化保持profile，无每分钟重分类。模式配置或手动覆盖、删除、许可变化routing_epoch++；结果检查target/epoch/config/许可后应用。

游戏模式首版只评论/回答，不操作游戏或注入输入。学习模式使用既有可验证来源和建议。响应按profile设置组合，不代码硬写学习专属DISCUSSION_PROMPT。手动游戏但黑屏只普通聊天，不编战况。

### 3.3 仲裁和上下文

所有后台任务共用2次/分钟、单in-flight、每类latest；用户问答不占背景额，先cancel后台再锁。route高于依赖profile的行为询问/主动讨论；已显式请求弹幕摘要属用户请求，不在后台自动循环。主动实际输出至少120秒，profile可更长，不能突破全局下限。

profile切换session/routing策略失效，停止旧后台/朗读；同材料仅profile变化可保留用户历史，但旧策略在途不可发。behavior episode模式签名带稳定ID+适用版本，改名称不丢关联，改场景需重评基线。

角色上下文独立profile_context/behavior_context advisory block，不改原用户消息、代码、diff、工具参数、授权。不把behavior预测当事实。视觉不可用在unavailable_preferences显示，普通文字仍可问。

## 4. 现有界面接线（P16）

- 现有陪伴详情：auto/manual选择、CRUD对话框、当前生效/候选/未知原因；原text/voice独立，目标及各通道状态继续保留。
- 连接与权限：前台范围、画面/文本发送、input features、排除、持久恢复、暂停/撤销；模式编辑里不偷偷管理授权。
- 数据与存储：行为库治理见行为文档；不在mode CRUD塞另一个数据管理。
- 桌宠原消息流：行为询问及反馈，回答保存笔记；不新增第二个chat。
- 现有用量：routing/behavior等计量。

控件使用tokens/既有表单和dialog，检查唯一入口；移动布局按现有矩阵，设计覆盖标新增和真实接线。回归DSH侧栏原生插件/轨迹/模型选择/审批等，禁止因设计没画而删。

## 5. 验收

P16：UI完成auto→manual→编辑→删除→重启，并独立测试持久观察新许可恢复、旧一次性不恢复、暂停不恢复。四屏/多宽度/缩放/主题与设计覆盖对照，零pageerror；所有原生功能保留。

实测分“路由机制正确”和“模型分类质量”。机制用假provider可确定验证；质量用真实已配置适用模型、标注样例集，报告逐场景结果和混淆，不用夹具冒称模型真懂。模型条件不足如实待验；游戏不支持画面/输入如实降级，不为了达标提权或下载新模型。
