# 本地模型能力上限与路由/估时策略（2026-10-19）

对象：笔记本 8083 常驻 **MiniCPM-V 4.7 35B-A3B IQ3_XS**（GTX 1060 6GB / 16GB RAM / i7-7700HQ），`-c 4096`、`--reasoning off`、`temperature 0`。目的：给主模型一个可执行的判断依据——哪些任务直接交本地、哪些给用户估时后选择、哪些默认主模型。

## 1. 测试方法

- 13 个任务，覆盖短分类、结构化抽取、多步数学、约束规划、代码、长文检索、翻译、摘要、未知/防编造、简单 OCR、复杂表格 OCR、视觉排序、严格格式。
- 通过 8083 OpenAI-compatible `/v1/chat/completions` 串行调用；JSON 任务带 `json_schema`；图像任务用受控 Edge 1280×720 渲染图。
- 单次运行、`temperature 0`、不启用 thinking；结果见 `.sumika-next/les/capability-results/`。
- 复杂表格夹具：6 行 × 5 列 + 预算柱状图 + 小字脚注；长文检索：约 420 prompt token 的运维记录，内含机柜/密码 needfact。

## 3. 延迟模型（用于估时）

实测热缓存：

- 短任务（40–90 prompt，10–30 output）：2.7–6.3s；t2 的 30s 属于偏慢样本。
- 中等输出（100–170 output）：14–25s。
- 多步数学 573 output：71s。
- 视觉：简单 15s、复杂 25s、排序 12s（热缓存）。

保守估时公式（给用户看的是范围，不是精确值）：

```text
warm_text  ≈ 3 + prompt_tokens / 20 + output_tokens / 7
warm_vision≈ 5 + prompt_tokens / 50 + output_tokens / 7
cold_first ≈ warm + 25   # 首次请求/模型刚换页
```

例子：

- 100 prompt / 100 output：3 + 5 + 14 ≈ 22s（实测 14–30s）。
- 500 prompt / 100 output 视觉：5 + 10 + 14 ≈ 29s（实测 15–25s）。
- 600 output 数学：3 + 4 + 86 ≈ 93s（实测 71s，保守）。
- 冷启动简单 OCR：15 + 25 ≈ 40s；极端冷缓存可到 57s。

估时必须以**实测日志**校准；模型换量化、换上下文、开 thinking 后要重测。

## 4. 路由策略

### A. 默认交本地（不询问）

- 短分类、意图、标签、情感、是否相关。
- 短 JSON/字段抽取（输出 ≤ 256 token，结构可校验）。
- 短翻译/短摘要/格式转换（输出 ≤ 200 token）。
- 简单、已知布局的 OCR（表格行数少、字段固定）。
- 低风险、可失败关闭、可重试的批处理。

这些任务本地热缓存通常 3–15s；冷启动可能 30–60s。UI 显示“本地处理中”，允许取消。

### B. 本地可选，给用户估时

- 多步数学、复杂规划、代码生成/解释。
- 长文摘要（输出 > 300 token）、长上下文检索（prompt > 1k）。
- 复杂表格/表单/图表 OCR，或逐字准确性要求高的 OCR。
- 角色一致性、长对话、需要保持人设的任务。
- 主模型判断“本地能做但会慢”的任务。

流程：主模型给出 **本地约 X–Y 秒 / 主模型约 Z 秒**，用户选择本地、主模型或取消；本地预计 > 60s 时提示“较慢”，> 180s 默认建议主模型。

### C. 默认主模型（本地不推荐/不提供）

- 高风险事实、财务/医疗/法律、需要外部最新信息。
- > 4k 上下文、多图/长文档、批量高并发。
- 实时语音/视频、要求 1–2s 首响。
- 需要工具调用、网页、代码执行等本地没有的能力。
- 用户明确要求最高质量。

## 5. 主模型判断与用户选择

主模型在派发前做三件事：

1. **分类**：任务属于 A/B/C 哪一档；不确定时按 B（给估时）而不是直接本地。
2. **估时**：按上面的公式和任务类别给范围；冷启动单独标注。
3. **给选择**：A 档默认本地但可取消；B 档必须让用户选；C 档默认主模型，本地仅作为用户坚持时的实验选项。

用户选择后记录：任务类别、选择、实际耗时、是否成功、失败原因，用于校准估时和路由。

## 6. 质量门与失败处理

- JSON：解析 + schema + 关键字段校验；失败不静默接受。
- OCR：行数/字段/关键数字校验；逐字高风险场景必须人工或主模型复核。
- 数学/代码：能自动验证的必须验证（答案、单测）；不能验证的标记“未验证”。
- 超时/断连：标记 unknown，不自动重试，不静默回退云端。
- 本地失败时报告原因，让用户决定重试/换主模型；不假装成功。

## 7. 能力边界（当前结论）

**能做**：短文本分类、结构化抽取、翻译、摘要、多步数学（预算足够）、约束规划、代码、长文检索、简单/中等 OCR、视觉排序、未知拒答、严格格式。

**不稳/不该单独做**：复杂表格逐字 OCR（已出现 1 字错）、高风险事实、长上下文 >4k、多轮角色一致性、实时/高并发、需要工具或外部信息的任务。

**时间上限**：热缓存短任务 3–15s；复杂 OCR 25s；多步数学 70s；冷启动可能 30–60s；更长输出按 ~7 token/s 线性增加。

## 9. 限制

- 单次运行、单夹具、`temperature 0`，不是统计显著性结论。
- 未测 thinking、多轮、多图、>4k 上下文、批量、工具调用。
- IQ3_XS 量化有质量损失；复杂 OCR 的 1 字错是实例，不是上限。
- 冷/热缓存差异大，估时需按现场状态修正。
