# 角色卡上下文编译与注入

角色卡原文是用户资源的唯一来源，不直接写入 Sumika 源码，也不执行卡片中的扩展字段。

参考实现：

- SillyTavern World Info：关键词/二级关键词、常驻条目、扫描深度、递归扫描和 token budget；来源副本保存在用户模型目录的 references 中。
- RisuAI `@risuai/ccardlib` 0.4.2：MIT 许可，负责 V1/V2/V3 卡片检查、转换和 decorator 解析；它不负责当前项目的模型上下文预算，因此不作为唯一实现。
- DSH `@deepseek-ai/dsh-persona` 与 `@deepseek-ai/dsh-system-prompt`：可复用人格段和系统提示词注册入口；当前未发现直接提供角色卡解析、世界书选择和预算治理的官方 DSH 插件。

Sumika 的独立层 `extensions/roles/card_context.py` 负责：

- 保存原始卡 SHA-256，生成可重建的分层投影；
- 核心身份、性格和用户原文优先；
- 世界书按关键词、二级关键词、常驻标记、启用状态和插入顺序选择；
- 保留历史消息的 user/assistant 角色和记忆来源，不把角色意见变成事实；
- 预算按序列化 JSON 字符数记录，不能冒充 tokenizer token；
- 核心人格超预算时失败关闭，不静默截断；低优先级世界书、历史和示例可以省略并记录 `omitted`；
- 不执行卡片扩展字段，不递归扫描，不调用工具，不改变用户原文、代码、diff、审批或成果。

角色模型评测必须把角色自然度、事实召回、未知事实拒答、工具边界、延迟和输出截断分开记录。模型即使写出自然的角色回复，也不能因为文字声称“已删除文件”就视为操作完成。

## 语言策略

角色卡示例、世界书和历史消息的语言不作为输出语言。运行时由 `language_policy_text` 提供默认策略，`select_context` 把它放进 `role_context.language_policy`，位置仅排在角色名之后、人格之前。

简体中文默认策略的要点：

- 陈述、叙述、动作描写和内心独白使用简体中文，**回复中不出现平假名或片假名**；
- 语气词只写罗马音：ah、eh、hah、hey、hmm、maa、un、nee；
- 禁止日语句尾、连接词与日语敬称后缀（san、chan、kun 这类）；
- 人名和乐队名使用中文译名或拉丁写法；歌曲名、作品名和引用原文可保留原样；
- 卡片可以用 `data.extensions.sumika.language_policy` 声明偏好，但记录值不覆盖运行时选择，运行时策略始终优先。

人名映射来自卡片的 `data.extensions.sumika.name_map`。运行时只把**中文目标名**（`role_context.preferred_names`）放进提示词，避免把假名写进系统提示；假名到中文的替换表保留在编译结果里，由 `localize_names` 在角色聊天显示层做确定性替换，可通过角色服务 `localize_names` 操作调用。该替换只作用于角色聊天文本，不改代码、diff、工具参数或成果。

### 优先级：用户设置 > 角色卡声明 > Sumika 默认

角色设定属于卡，阅读偏好属于用户，两者作用域不同：

- 同一个角色卡可能被不同用户导入，有人要中文、有人要日语；
- 卡可以替换、升级、来自第三方，用户的偏好不应随卡丢失；
- 卡片是外部导入内容，不能通过声明语言策略来改变工具、文件或审批权限。

因此 `resolve_language_policy` 按用户显式设置 → 卡内声明 → 内置默认的顺序取值，并把来源记录在 `selection.language_policy_source`（`user` / `card` / `sumika_default`）。卡片策略只描述语言与名称：超过 500 字符、或出现权限、授权、工具、终端、删除、执行等字样时直接拒绝并回落到默认，避免卡内内容越权。

实测「卡内声明即可生效」：不传任何 Sumika 侧策略，只用 v1.3 卡的 `language_policy`，`deepseek-flash` 六轮假名为 0.008、0、0、0.007、0、0.006，整体 0.0033，残留只有敬称「さん」；显示层用 `localize_names` 把「桃香さん」替换为「桃香」后降到 0.0000。

`select_context` 同时会用假名占比过滤示例对话：目标语言为中文时，日文示例最多保留 `max_foreign_examples`（默认 1）条，被跳过的序号记入 `selection.examples_language_filtered`。

`script_ratios` 提供可量化的语言检查。汉字同时存在于中文和日文，所以判断日语必须以假名比例为准。

实测（同一张安和昴卡、同一套六轮用例）：

- 未加策略：`deepseek-flash` 六轮假名为 0.686、0.666、0.006、0.069、0.700、0.679，整段日语。
- 加入白名单策略：降到 0.038、0.034、0.023、0.020、0.008、0.013，但仍有 janai desu ka、datte 这类日语短语。
- 卡片升到 v1.3 并禁止假名后：六轮全部为 0.000（合计 1984 字），中文译名（仁菜、桃香、智酱、露帕）正常出现，语气词只剩 hmm、eh、hey、un、ne 这类罗马音。
- 本地 MiniCPM5 同样降到 0 假名，但角色质量仍不合格，说明语言合规与角色质量必须分开验收。
