# 普通聊天自动提炼的门槛（2026-09-15）

背景：P6-3 此前只支持“用户明确说记住”的写入路径。普通聊天要不要自动记、由谁决定，属于策略问题；先把它写成确定性规则，避免以后由模型自由决定往长期记忆里写东西。

## 分层

1. **提议层（可替换）**：模型或规则从对话里提出候选事实，携带 `text`、`kind`、`confidence`、`message_ids`、可选 `fact_key`。
2. **裁决层（本模块）**：`extensions/memory/extraction_policy.py` 决定哪些候选可以写入。提议层可以换模型，裁决规则不随模型变化。
3. **写入层**：沿用既有 `MemoryWriter`/`EmbeddedMemory`，保留来源与事件绑定。

## 规则（全部可测）

| 规则 | 说明 | 拒绝原因 |
| --- | --- | --- |
| 置信度门槛 | 默认 `0.8`，`>=` 通过，`<` 拒绝 | `below_threshold` |
| 必须可追溯到用户消息 | `message_ids` 与本次用户消息有交集，模型自己编的 id 不算 | `not_traceable_to_user_message` |
| 角色意见不得当作用户事实 | `source == "role_model"` 或 `kind == "opinion"` | `role_opinion_is_not_a_user_fact` |
| 凭据一律不入库 | 匹配 `sk-`、`Bearer`、`password=`、`token=`、长十六进制串 | `contains_credential` |
| 长度上限 | 默认 200 字符 | `too_long` |
| 类型白名单 | 仅 `preference` / `fact` / `relationship`；`event` 等不入长期记忆 | `kind_not_allowed` |
| 去重 | 归一化后与已有文本相同则跳过 | `duplicate` |
| 每轮写入上限 | 默认 3 条，超出部分丢弃 | `turn_limit` |
| 同键更新 | 同 `fact_key` 的新值允许覆盖旧值（由写入层置旧值为 inactive） | — |

归一化会忽略空白与换行差异，但内容不同即视为不同事实。

## 为什么这些规则

- 陪伴场景里最容易出问题的是“角色自己的推测被写进用户档案”。因此意见类一律拒绝，且要求可追溯到用户原话。
- 凭据类内容一旦写入就很难清理，直接在最外层拒绝。
- 每轮上限与去重避免模型絮絮叨叨把同一件事写十遍。
- 阈值用常量而不是散落在调用点，方便以后用评测调参。

## 当前接线与限制

- 规则提议层已接入 RoleChat，使用持久化用户消息 ID；auto_extract 默认关闭。memory.enabled 关闭时聊天不检索、不注入、不自动写入，但保留显式管理。
- 仅处理整条消息为简单自述的情况；引用、假设、疑问、否定及含糊的“改用/改成”不自动记忆。不同爱好使用独立稳定键，姓名和当前住址仍可同键更新；不迁移或删除已有记忆。
- confidence 必须是有限的 0–1 数值，布尔值不接受。消息 ID 只证明来源关联，置信度也不能证明内容正确；裁决层不具备语义真值验证能力。
- 模型提议层已接线：memory.model_proposals 默认关闭，随同一次角色回复生成候选（会增加输出用量），无二次提取请求。原话必须逐字出现在本次用户消息中，正文与原话均过凭据过滤；宿主绑定消息ID，不采纳模型提供的fact_key。候选保存在原有memory_proposals中，不参与检索，用户在既有记忆管理窗口确认后以user-confirmed来源保存。忽略与确认状态、来源原话均支持重启及导出恢复。消息关联仍不能证明语义正确，确认界面保留这一判断。
- 否定偏好及复杂纠正暂需显式管理，不宣称已支持所有事实更新。当前 57 项相关测试通过，真实 Edge 已核验记忆开关可见；最终本地Qwen3 8B合成对话验收通过；零云端请求。

任务意图和记忆提议共用同一次回复的单一JSON附注，避免两个输出标记互相干扰；宿主额外拒绝明显假设、小说引用等候选来源。最终真实模型三例结果记录在 desktop-integration-execution.md。
