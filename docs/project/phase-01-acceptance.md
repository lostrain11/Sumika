## 实际限制与纠错

- 初次探测误用了 rc.1 的旧请求格式；rc.2 HTTP 200 内返回业务错误，不计通过。适配器现在核对完整 RPC 封装、rpcId、ok 和业务值，新增负例避免再次误报。
- 本机 Python 没有全局 setuptools，`--no-build-isolation` 构建失败；改用 pyproject 声明的隔离构建后成功，没有修改全局 Python 包。
- 当前事件流是 Sumika 派发日志。DSH 的完整 follow/流式事件、活跃模型任务取消、文件/终端/子 Agent/Skills/MCP 工作闭环在 P2 验收。空闲取消不是活跃任务取消证据。
- 进程内宿主代码和用户本机账号是信任边界，不声称抵御同用户恶意代码或提供 OS 沙箱。原生 DSH UI 的行为遵循其原生策略；P1 没有添加可绕过认证的代理 API。
- rc.2 是阶段 0/1 固定且通过生命周期验收的发行，尚不是完整日用验收版。日用切换与角色扩展尚未发生。
- 交接验收使用独立进程/隔离文件记录重建和校验，未调用第二个付费模型进行主观判断。
