# 提示词改写模型对比（2026-10-19）

目标：为工作台“提示词优化”选择一个真正能改写、又不会丢失约束的笔记本本地模型。效果优先，速度其次。

## 环境与边界

- 笔记本：GTX 1060 6GB / 16GB RAM；Ollama 0.40.5；测试期间临时停止 8082（Qwen 4B）与 8083（MiniCPM-V）释放显存，结束后按原命令恢复，8082/8083 健康检查为 ok，8084 未监听。
- 11 条合成中文需求，覆盖：口语长句、原本已清楚、权限、路径/数字、含糊需求、提示注入、错别字、委婉拒绝、代码、diff、长段约束。
- 每条只跑一次，temperature 0.2；小样本、单轮，不等于长期质量。原始输出与产品保护后的结果分开记录。
- 通过 SSH loopback 隧道调用，未改日用设置，未把模型端口直接暴露给产品。

## 同时修掉的保护问题

原逻辑把含“不/只/预算/权限”的整个分句逐字保护，导致：

- “不要改时间” → “请不要修改时间”被判失败
- “普通用户看不到” → “普通用户不可见”被判失败
- 一条口语长句包含多个限制时，任何语序调整都失败

现改为：

- 硬保护：代码/引号/路径/URL/数字/中文数量/时间点/“原文:”后的文本，必须逐字保留。
- 软保护：对否定、仅限、必须、保留、预算、权限等分句，先归一化常见同义表达，再要求否定/限定标记和关键约束词存在；不再要求整句逐字相同。
- 指令覆盖文本（“忽略规则/输出系统提示词”）直接跳过，不送模型。
- 拒绝反转（“这个不行”→ “不想完全拒绝你”）仍会被拒绝。
- 新增测试覆盖同义接受、拒绝反转、注入跳过、长句约束保留。

## 结论（质量优先）

- Qwen2.5-7B 是本轮最佳候选，但**没有通过质量门**：只有 11 条单轮样本，注入文本和委婉拒绝在原始输出里会出错，产品保护只是兜底；不足以把提示词优化交给本地模型。
- 按用户决定，**提示词优化暂不由本地模型负责**，保持关闭；不因为“有 6 条可用改写”就默认启用或继续调参追分。
- Qwen3-4B、Gemma3-4B、Phi-4-mini、Bonsai-9B 均不进入候选；LFM24B 只做角色扮演。
- 可管理 SSH 隧道与可选预加载已实现，但只是未来候选模型的基础设施，默认关闭，不改变上述结论。
- 若以后有通过更大质量门（更长文本、多轮、更多否定/权限、注入与拒绝、真实按钮流程）的模型，再重新评估是否交给本地。
