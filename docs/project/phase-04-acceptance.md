## 实现与边界

| 需求 | 实现及证据 |
| --- | --- |
| 任务开始保存原文与目标 | 原生收件箱和已接纳消息按稳定消息 ID 保存；保留文本、来源与顺序。目标报告与原文分开，通过来源 ID 关联；被拒绝的提示也不会因此成为授权。 |
| 计划变更 | 专用工具保存新计划、前一计划内容/ID、原因和受影响任务；不覆盖历史。 |
| 阶段/任务结束 | Skill 指导记录已实现、验证声明、未完成、限制和下一步；原生回合结束自动保存观察记录和可恢复视图，不猜测完成情况。 |
| 压缩、重启、模型交接 | 压缩事件保存视图；下一轮或压缩后注入来源为 plugin 的交接；恢复原会话补记缺失事件并去重。新会话可查询同一项目的原任务，原始消息与摘要独立。 |
| 项目/任务/会话/Git 关联 | 独立项目 UUID、任务 ID、原生会话和事件/消息 ID、Git HEAD、UTC 捕获时间。没有 Git 时 HEAD 明确为空；未提交改动仍核对实际 diff。 |
| 查询状态/决策/来源/下一步 | continuity_query 支持当前视图和按任务/类型/序号分页；goal/plan/decision/outcome 保留 sources 和 uncertainties。 |
| 推断和原文边界 | 观察记录为 host_observation，模型填写为 model_report；不产生审批，不修改既有 phase_status。代码、diff、正文和插件上下文分开。 |
| R-105 / R-106 架构 | extensions/continuity/continuity.py 标准库独立实现；dsh.mjs 只做 DSH 事件/工具/上下文适配；未修改上游源码或 Sumika 执行核心。 |
| R-107 / R-108 开关 | enabled=false 时不捕获、不注册工具、不注入上下文，保留数据；当前通过 profile 配置及重启使用，设置 UI 尚未实现。 |

当前项目已安装到 `.sumika-next/daily/0.1.5-rc.2`；在项目根运行 `python -B -m sumika_next.cli run` 使用该 profile。其他项目需按 [扩展说明](../../extensions/continuity/README.md)显式登记。源码检出本身不携带本地 profile 或私有记录。

复用选型核对了发行包内官方 Claude Code/Codex Hook 桥：其压缩事件和来源保真限制不满足本阶段要求，因此复用原生插件事件及 tools 接口，并以薄中间层接独立代码。没有重新实现 Agent 循环，也没有另建 UI。

## 限制、回退与下一步

模型仍须按 Skill 使用专用工具填写语义报告；未填写时记录保留原文/事件并明确缺少结果，不强制启动另一次模型调用。上游强制终止可能先于后台记录完成，重新启用并恢复原会话后从持久日志补记。禁用不抹除历史，重新启用时可能补记禁用期间的原生日志。

自动捕获仅对登记的会话 cwd 生效，不自动扩大到其他项目。附件仅保留事件中的引用/内容表示，外部文件需独立备份。私有原话可能包含敏感内容，`.sumika-continuity/` 默认忽略、不上传，不能用 Git bundle 代替该目录的私有备份。

回退：关闭 enabled 或移除该插件条目并重启 DSH，保留数据库和原生 profile；必要时恢复安装前 patch 的备份，先检查后续配置变更，不能覆盖其他新设置。独立数据库可脱离 DSH 查询与生成交接。

下一阶段为 P5：办公文件与桌面助手能力；统一设置界面待 UI 设计时接入。验收索引及本地产物哈希见 [phase-04-evidence.json](phase-04-evidence.json)。
