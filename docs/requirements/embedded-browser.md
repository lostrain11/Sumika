## 用户可见的结果

Sumika 自己提供一个受管理的内置浏览器工作区，网页任务通过统一入口、标签页、操作状态和人工接管完成。无需用户在多个自动弹出的独立浏览器窗口间切换。这是产品需求，不是 Codex 当前内嵌浏览器的能力承诺。

| 网页场景 | 内置浏览器中的预期行为 | 关联 |
| --- | --- | --- |
| 网页聊天与辅助咨询 | 从当前任务打开对应站点，查看状态、审查结果、追问或接管 | `BROWSER-004`、`TASK-002` |
| 注册、登录、验证码与授权 | 在原任务标签页交给用户操作，完成后继续；不把密码、OTP交给模型 | `BROWSER-003`、`PROVIDER-003` |
| 官方价格、资源包和余额 | 显示来源、观察时间、账户绑定及过期状态；必要时DOM或本地OCR读取 | `MODEL-015`、`MODEL-016` |
| 福利查看、领取和签到 | 从发现结果进入原站，复用已授权免费操作，展示到账或具体阻碍 | `BENEFIT-001`、`BENEFIT-002` |
| 新站需要用户操作 | 明确指出需注册、实名、Key或验证，允许暂缓；不把未配置站点设为可路由 | `BENEFIT-001` |

官方公开API、RSS和不需要网页交互的后台解析继续使用脚本。内置浏览器统一的是需要网页的用户流程，不把高频维护改成额外模型调用或强制网页点击。

## 由原意归一化的验收边界

以下是实现约束，不冒充用户逐字指定了某个浏览器引擎或控件布局：

1. **入口和档案**：同站同账户可复用受管登录；不同账户明确隔离。任务能定位对应页面与账户。不得静默合并现有BrowserSkill、门户或咨询档案，不导出Cookie，不读取个人浏览器数据。
2. **人工接管**：运行中能看到目标、阶段、结果与阻碍；用户接管时自动写入暂停，同一档案只允许一个写入者。完成接管后恢复原任务，不从头重复提交。
3. **已有授权持续有效**：普通网页咨询、明确免费的领取/签到按已有范围执行，不为每次相同行为重复询问。注册/实名/验证码、充值、未知付费和新增权限仍按实际边界处理。
4. **失败可恢复**：区分未发送、已发送、结果未知、取消和站点失效。提交未知不重发；发现限免撤回不能静默走现金；日志不保存页面正文、截图或凭据。
5. **生命周期**：关闭标签页、切换客户端/桌宠、最小化、关闭和重启均有明确恢复行为；不重复启动后台。应用关闭停止联网维护，只清理本实例资源。
6. **兼容例外**：遇到禁止内嵌或不支持的站点，明确显示限制、受影响功能与用户可见的替代路径；不得偷偷弹外部窗口并宣称已统一。无需为了统一重写受支持的官方API。
7. **引擎可替换**：Tauri WebView、BrowserSkill或后续适配器是工程选项；Sumika掌握权限、账户归属、任务生命周期及审计。不能把BrowserSkill选型或Codex工具可用性写成产品必须依赖的事实。

## 后续验收场景

- 从Sumika打开聊天、账户额度页和福利页，切换标签与账户不混淆；正常路径不弹独立窗口。
- 用户在内置页完成登录/验证码后，任务回到原阶段；过期登录显示接管状态。
- 自动签到与用户手动操作竞争时互斥；重复启动或未知提交不重复领取，到账证据与提示分开。
- 模型价格由限免转付费、官方页解析失败、网页离线、用户取消时保留证据并阻断不满足契约的执行。
- 重启、关闭、桌宠切换和不兼容站点例外均可恢复；确认没有Cookie迁移、无关进程关闭或内容泄漏。

测试应先用隔离页面和账户契约验证，再按已授权真实站点逐项验收；一个站点通过不能代表所有站点通过。
