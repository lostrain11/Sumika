# Sumika 项目需求

## 目标

深度基于 DSH 最新发布版本（包含 RC），优先复用其已实现功能，先实现 Codex 日用开发平替。

## 当前范围

- 使用 DSH 原生 Web UI。
- 支持完整开发工作流：代码阅读、搜索、修改、测试、终端操作、规划与执行、Skills/MCP、子 Agent、代码审查、会话恢复和工作区管理。
- 首版实现需求原文与项目进度的持久记录，支持有限上下文下持续工作、其他模型中途接手，以及未来更强模型重构项目。
- 以实际开发任务能够完成作为验收依据。
- 暂不考虑 Sumika UI、自动选模、免费渠道发现和复杂费用系统。其他需求后续逐项明确、逐项加入。

### 需求与项目连续性（首版必做）

- **需求原文**：持续保存用户在项目推进中提出的需求、补充与修改，保留来源和先后关系；区分用户原话与模型整理，后续变更不覆盖历史原文，并明确当前有效需求。
- **总计划与阶段计划**：记录项目目标、总体计划、阶段划分、各阶段任务与验收条件；计划修订保留变化及原因，能追溯到对应需求。
- **进度与实现程度**：持续更新已实现、部分实现、未实现、受阻的功能和任务，记录当前阶段、完成到哪一步、剩余缺口与下一步；区分代码实现、验证通过和实际可用，不以模糊百分比代替依据。
- **可恢复交接**：记录关键决策、约束、验证结果和相关代码或成果位置。上下文压缩、会话重启或更换模型后，先读取紧凑的当前状态，再按需查阅原文和详细记录，避免遗漏需求、任务目标或重复已完成工作。
- **持久与可迁移**：记录独立于当前模型上下文，支持其他模型读取；在需求、计划、阶段成果或阻碍变化时及时更新。摘要不能替代原始记录，缺失或未核实的内容明确标记。
- **验收**：由未参与前文的模型仅依靠项目记录，能够找回需求原文、说明有效目标与计划、辨认各项完成程度，并从准确的下一步继续工作。
- **项目与任务管理**：复用 DSH 提供的项目、工作区、会话和任务能力，按项目组织代码、对话、需求和成果，支持暂停、恢复、取消、重试与交接；Sumika 只补充需求原文、阶段进度、验证状态和连续性交接记录，不重复实现已有 Agent 客户端能力。

## 实现原则

> 接入方式尽量融入 DSH，新增能力的核心逻辑尽量独立。

- 优先使用 DSH 已有能力，只补实际功能缺口。
- 补充功能时，优先复用合适且高质量的 DSH 社区插件或开源项目；只有没有满足要求的现成方案时，才自行实现。
- 根据功能选择最合适的接入方式，例如插件、MCP、Skill 或独立工具。
- 可复用的核心逻辑与 DSH 接入部分分离，避免依赖其私有结构，为未来更换 Harness 保留空间。
- 不为独立性过度拆分或增加不必要的框架。
- 按需参考、复用已有代码和工具，节省开发时间与成本。
- 按全新项目设计，不受既有实现约束；参考代码按质量和适配成本选择，不合适时可以不参考或重新实现。

## 版本更新

持续跟进 DSH 最新发布版本，包括 RC。每次锁定具体版本，验证后切换，并保留可回退的运行版本。

## 未来计划

以下为长期方向，后续逐项确定实现范围和顺序，不作为当前首版前置条件。

### 桌面助手的工具与能力

- **项目数据备份与恢复**：支持备份和恢复聊天、需求原文、计划、进度记录、角色配置等项目数据，暂不考虑加密。
- **远程访问与手机端**：支持从手机或其他设备连接桌面助手，查看任务进度与成果、继续会话、发起任务和处理审批；任务在所连接的主机执行。先考虑复用现有 Web 与远程连接能力，后续支持 Android 客户端；连接具备身份认证和可撤销的设备授权。
- **按需添加的能力模块库**：未启用的功能默认收起，通过“＋”选择添加；模块支持排序和移除，添加模块、启用功能与授予权限分别处理。OCR 与截屏翻译等工具按此方式组织。
- **同一能力的实现切换**：用户可为同一能力选择和切换不同实现，例如本地或云端 OCR、不同语音合成引擎；能力模块与具体实现分离，界面展示可选实现及当前选择。
- **OCR 与截屏翻译**：识别和提取图片或选定屏幕区域中的文字，并支持翻译。这属于桌面助手自身的工具与能力，可独立用于日常任务，也可供角色陪伴调用。
- **通用桌面软件使用与控制**：助手能够理解桌面界面，通过观察、点击、输入、快捷键和窗口操作使用软件，并根据任务利用软件本身的能力。面向通用桌面操作，不以逐个应用专门适配为前提；Blender、Obsidian 等是使用场景示例，不是限定支持列表。用户可接管或停止操作，尽量减少对其他工作的干扰。
- **办公文件处理（首批扩展任务）**：支持文档、表格、演示文稿和 PDF 的读取、创建与修改。优先复用已有 DSH 社区插件或高质量开源工具，先完成常见基础操作，再按实际需要扩展高级排版、公式和模板能力。
- **定时任务**：支持一次性、每日或每周执行任务，以及时区、暂停、修改、立即执行和结果历史。优先复用 DSH 已有调度能力，按实际缺口补充，区分到时提醒与真正执行任务。
- **网页 AI 咨询**：任务需要时可向已登录的网页 AI 咨询，由主 Agent 审查并综合意见。咨询来源数量不设固定上限，按任务需要选择。
- **内置浏览器统一管理咨询页面**：复杂任务的网页咨询、相关登录与人工接管集中在内置浏览器中，通过内部标签页管理多个来源；不向外部 Edge 弹出一堆窗口或标签页，保持界面美观整洁，后台咨询不抢占用户当前视图。
- **免费／限免模型权益发现与领取（以后再考虑）**：自动搜集相关资讯和免费额度，在支持且已授权的站点领取权益、签到。仅保留为远期候选，暂不展开设计或安排实施。

### 角色陪伴与生活

在日用开发助手基础上，逐步发展为有独立人格、记忆和生活的角色陪伴系统。

角色相关功能作为首版日用开发目标完成后的首批扩展任务，分阶段推进，不要求一次实现全部生活与多角色愿景。

- **工作模型与角色模型分开配置**：开发工作和角色聊天可分别选择模型。保留角色上下文注入；开发工作状态下，角色口吻和附言不得改写或混入原始内容、代码及工作成果正文，角色表达与工作正文分开。
- **可管理的长期记忆（确定实现）**：跨会话记住用户偏好和共同经历，支持查看、修改、删除、导入导出，并逐步支持自动记忆与按需回忆。优先比较现成 DSH 插件和开源记忆方案，以实际场景效果选优，不预先绑定产品；重点验证中文与长期经历回忆、事实更新、多角色隔离和误召回，兼顾延迟、成本及迁移能力，不仅依据项目自报榜单。
- **角色资源导入与管理**：支持导入角色卡、2D／3D 角色模型、角色语音模型及场景资源；以本地资源包管理，支持版本管理，并可为角色选择和更换相应资源。
- **角色世界书与背景设定库**：保存角色背景、人物关系和世界设定，按对话需要读取并注入角色上下文；与记录实际共同经历的长期记忆区分，开发时遵守角色表达与工作正文分离的要求。
- **角色主题与界面配色自定义**：界面主题和配色可随角色风格调整，支持用户自定义，不固定为单一色调。
- **语音与感知**：角色可以与用户语音交流，观察经用户允许的屏幕或摄像头内容；先支持按需交互，再逐步支持实时反馈。
- **陪看与游戏陪伴**：一起看视频、观看用户打游戏，理解当前内容并聊天、评论或吐槽。
- **实际参与游戏**：进一步让角色作为玩家参与游戏，通过适合具体游戏的插件或接口实现，与只观看和评论的陪伴模式区分。
- **虚拟居所与自主生活**：角色拥有自己的房间和生活空间，按日程及有限主动性进行吃饭、睡觉、工作等活动，也能对用户互动做出反应，例如用户开始工作时走到书房电脑前。
- **摄像头视角与桌宠**：用户通过虚拟世界中的固定或跟随摄像头观察角色生活；桌宠可以作为同一角色和世界的一个观察窗口，与居所视图保持状态一致。
- **桌面壁纸陪伴模式**：可将客户端全屏固定在桌面最底层，让角色和居所作为桌面背景持续展示，提供类似学习陪伴游戏的体验。
- **多角色共同生活**：未来可同时启用多个角色，各自拥有独立人格、形象和记忆，在同一房屋生活、同屏出现、彼此交流，并共同陪伴用户。记忆默认独立，共享由用户明确选择。
- **现实设备接入**：连接摄像头、传感器或遥控小车等设备，作为角色感知和行动的延伸；先实现局域网发现和只读感知，再逐步加入经过明确授权的设备控制。
